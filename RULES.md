# RULES.md — Règles non-négociables

> Tout ce qui est écrit ici prévaut sur le reste de la doc. Aucune exception sans autorisation explicite.

## Git & livraison

- **JAMAIS** de `Co-Authored-By`, `Generated by`, ou toute attribution IA dans les commits.
- **Pas de merge, pas de PR, pas de push sur `main`** sans approbation explicite de l'utilisateur.
- **Pas de force-push** sur quoi que ce soit qui partage l'historique avec `main`.
- **Pas de `--no-verify`** (jamais skipper les hooks). Si un hook échoue, on corrige la cause, on ne contourne pas.
- Une branche par carte : `[ID]-[nom-de-la-fonctionnalite]` (ex. `10-permissions-entites`).
- Avant chaque commit : `git status` + vérification `.gitignore` (jamais commiter `.env`, secrets, dumps, `docs/opportunity.csv`).
- Commits atomiques. Plusieurs sujets = plusieurs commits.

## Norme de commit : Gitmoji + Français

### Format
```
<emoji> <description en français à l'impératif présent>
```

| Emoji | Code | Utilisation |
|-------|------|-------------|

### Valides
```
✨ ajoute l'objet InternalEntity via le Metadata Engine
🗃️ migre les opportunités existantes vers la structure multi-entités
🔒 intercepte les requêtes calendrier inter-entités
```

### Invalides
```
feat: add entity selector      ← pas d'emoji, pas en français
✨ Added InternalEntity         ← passé composé, pas impératif
✨ add InternalEntity           ← en anglais
```

## Protocole d'exécution par carte

Lorsqu'une carte `[ID]` est demandée :

1. Créer et basculer sur la branche `[ID]-[branch-name]`.
2. Lire les critères d'acceptation dans `docs/ROADMAP.md`.
3. Identifier les fichiers affectés **avant** d'écrire du code.
4. Lire chaque fichier cible (ne jamais modifier du code non lu).
5. Implémenter en respectant SRP + Clean Architecture (voir `docs/CONVENTIONS.md`).
6. Vérifier la qualité (voir `docs/WORKFLOW.md` — typecheck + lint diff).
7. Lister tous les fichiers modifiés.
8. **STOP** — Aucun merge, aucune PR.

## Code

- **Zéro `any`** en TypeScript. Strict mode systématique.
- **Pas d'abréviations** (`fieldMetadata`, pas `fm` ; `user`, pas `u`).
- **Pas de commentaires inutiles** : un commentaire explique le *pourquoi non-évident*, pas le *quoi*.
- **Pas de fallback ni d'error handling pour des scénarios impossibles**. Valider uniquement aux frontières (input utilisateur, API externe).
- **Pas de refactoring opportuniste** : un bugfix corrige le bug, point. Pas de nettoyage de surface.
- **Pas de fichiers de doc créés spontanément** (README, *.md) sans demande explicite.

## Sécurité

- SQL : identifiants table/colonne échappés explicitement, données via placeholders (`$1`, `$2`). Une query n'est "préparée" que si les valeurs dynamiques passent dans `values`, jamais interpolées dans `text`.
- Header HTTP `ACTIVE_INTERNAL_ENTITY_ID_HEADER_NAME` : normaliser via `normalizeOptionalEntityId` côté serveur (trim + lowercase) avant tout usage.
- Privacy calendrier : tout nouveau champ qui peut leak l'entité doit être ajouté à `applyWorkspaceCalendarEventMask` / `applyTimelineCalendarEventMask`. Voir `docs/ARCHITECTURE.md` section "Audience de calendrier".

## i18n

- Identifiants i18n explicites en anglais, stables, sans espaces ni caractères spéciaux.
- Ne pas renommer en masse des clés i18n sans besoin clair de migration.
