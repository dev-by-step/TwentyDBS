# CLAUDE.md — Index de session

> Premier fichier à charger en début de session. Ne contient **pas** de règles ni de code : c'est un index qui pointe vers les sources de vérité.
> Pour les décisions structurantes, l'état d'avancement et les pièges connus → `MEMORY.md`.

---

## Identité du projet

- **Nom :** Twenty CRM Multi-Entity (fork de `twentyhq/twenty`)
- **Stack :** Nx + Yarn 4 monorepo. NestJS + GraphQL Yoga (back), React 18 + Vite + Jotai + Linaria (front), TypeORM + PostgreSQL + Redis + BullMQ.
- **Démarrage local :** `yarn dev`
- **Branche par défaut :** `main`

## Architecture des docs Claude

```
/
├── CLAUDE.md         ← (ce fichier) index de session
├── MEMORY.md         ← contexte persistant : état, décisions, pièges connus
├── RULES.md          ← règles non-négociables (commits, branches, sécurité)
└── docs/
    ├── ROADMAP.md       ← cartes fonctionnelles + critères d'acceptation
    ├── ARCHITECTURE.md  ← architecture technique multi-entités
    ├── CONVENTIONS.md   ← conventions de code Twenty
    ├── WORKFLOW.md      ← commandes Nx, débug, init multi-entités
    ├── REVIEW.md        ← checklist des retours de revue récurrents
    └── AUDIT-BACKLOG.md ← backlog vivant des bugs (FIX-XX) et améliorations (IMP-XX) issus des audits — à mettre à jour à chaque correctif
```

## Ordre de lecture recommandé

1. **`MEMORY.md`** — comprendre où on en est (état des cartes, décisions, pièges actifs).
2. **`RULES.md`** — assimiler les règles non-négociables (commit, branches, sécurité).
3. **`docs/ROADMAP.md`** — repérer la carte en cours et ses critères d'acceptation.
4. **`docs/ARCHITECTURE.md`** — comprendre le modèle de données et les couches.
5. **`docs/CONVENTIONS.md` + `docs/WORKFLOW.md`** — patterns de code et commandes.
6. **`docs/REVIEW.md`** — checklist avant de marquer une carte "done".

## Quick start

```bash
# 1. Lancer l'app
yarn dev

# 2. Sur reset DB ou nouvelle relation multi-entités, relancer :
npx nx run twenty-server:command -- init-internal-entities
npx nx run twenty-front:graphql:generate

# 3. Avant chaque commit :
npx nx typecheck twenty-server && npx nx typecheck twenty-front
npx nx lint:diff-with-main twenty-server && npx nx lint:diff-with-main twenty-front
```

## Garde-fous critiques (rappels prioritaires de `RULES.md`)

- **JAMAIS** de `Co-Authored-By` / `Generated by` / attribution IA dans les commits.
- **Pas de merge, pas de PR, pas de push sur `main`** sans approbation explicite.
- **Pas de `--no-verify`** : si un hook échoue, on corrige la cause.
- Une branche par carte : `[ID]-[nom]`. Norme de commit : Gitmoji + français impératif.
- Multi-entités : après tout changement de metadata, relancer `init-internal-entities` + `graphql:generate`.
