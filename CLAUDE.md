## RÈGLES PROJET (Non-Négociables)

- **JAMAIS** de `Co-Authored-By`, `Generated by`, ou toute attribution IA dans les commits
- **Pas de merge, pas de PR** sans approbation explicite de l'utilisateur
- Une branche par ID : `[ID]-[nom-de-la-fonctionnalite]`
- Commits atomiques — norme **Gitmoji + Français** (voir section dédiée ci-dessous)

## PROTOCOLE D'EXÉCUTION PAR CARTE

Lorsqu'une carte [ID] est demandée :

1. Créer et basculer sur la branche `[ID]-[branch-name]`
2. Lire les Critères d'Acceptation dans `docs/ROADMAP.md`
3. Identifier les fichiers affectés **avant** d'écrire du code
4. Lire les fichiers cibles (ne jamais modifier du code non lu)
5. Implémenter en respectant SRP + Clean Architecture
6. Vérifier après chaque changement :
   ```bash
   npx nx typecheck twenty-front
   npx nx typecheck twenty-server
   npx nx lint:diff-with-main twenty-front
   npx nx lint:diff-with-main twenty-server
   ```
7. Lister tous les fichiers modifiés
8. **STOP** — Aucun merge, aucune PR

## TWENTY — COMMANDES DE DÉVELOPPEMENT

### Démarrage
```bash
yarn start                              # frontend + backend + worker
npx nx start twenty-front              # frontend seul
npx nx start twenty-server             # backend seul
npx nx run twenty-server:worker        # worker seul
```

### Qualité de code (toujours exécuter après un changement)
```bash
npx nx lint:diff-with-main twenty-front    # lint diff uniquement (préféré)
npx nx lint:diff-with-main twenty-server
npx nx typecheck twenty-front
npx nx typecheck twenty-server
npx nx fmt twenty-front                    # formatage
npx nx fmt twenty-server
```

### Tests
```bash
npx nx test twenty-front
npx nx test twenty-server
npx nx run twenty-server:test:integration:with-db-reset
npx jest path/to/test.test.ts --config=packages/PROJECT/jest.config.mjs  # un seul fichier
```

### Base de données
```bash
npx nx database:reset twenty-server
npx nx run twenty-server:database:init:prod
npx nx run twenty-server:database:migrate:prod
npx nx run twenty-server:database:migrate:generate --name <name> --type <fast|slow>
```

### GraphQL
```bash
npx nx run twenty-front:graphql:generate
npx nx run twenty-front:graphql:generate --configuration=metadata
```

### Setup environnement dev
```bash
bash packages/twenty-utils/setup-dev-env.sh         # setup standard
bash packages/twenty-utils/setup-dev-env.sh --docker # forcer Docker
bash packages/twenty-utils/setup-dev-env.sh --reset  # reset complet
```

## TWENTY — CONVENTIONS DE CODE

- **Composants** : fonctionnels uniquement, exports nommés uniquement
- **Types** : `type` plutôt qu'`interface` (sauf extension de types tiers)
- **Enums** : string literals préférés (sauf enums GraphQL)
- **Zéro `any`** — TypeScript strict
- **State global** : Jotai (atoms, selectors, atom families)
- **Styling** : Linaria (zero-runtime CSS-in-JS)
- **i18n** : Lingui
- **Fichiers** : kebab-case + suffixe (`.component.tsx`, `.service.ts`, `.entity.ts`, `.dto.ts`, `.module.ts`)
- **Pas d'abréviations** : `fieldMetadata` pas `fm`, `user` pas `u`
- **Helpers** : utiliser `isDefined()`, `isNonEmptyString()`, `isNonEmptyArray()` depuis `twenty-shared`
- Composants < 300 lignes, services < 500 lignes

## TWENTY — ARCHITECTURE BACKEND

- Changement d'entité → générer une **instance command** (`database:migrate:generate --name <name> --type fast|slow`)
- **Fast** = changement de schéma ; **Slow** = migration de données (`runDataMigration`)
- Toujours inclure `up` et `down` dans les instance commands
- Ne jamais réécrire le `up`/`down` d'une instance command déjà committée
